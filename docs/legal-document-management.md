# 用户协议与隐私政策管理

后台入口：**协议与隐私管理 → 用户协议 / 隐私政策**。

## 日常更换流程

1. 选择 `.docx` 文件（最大 5 MB）。旧版 `.doc` 请在 Word 中另存为 `.docx`。
2. 核对导入预览，点击「用此正文替换本地草稿」。取消导入不会改动当前正文。
3. 填写文档标题、生效日期、版本号；更新日期、导语和更新说明可选。导入会将更新日期设为当天（北京时间），生效日期仍需单独确认。
4. 可在正文编辑器调整标题、段落、粗体、斜体、下划线及列表，展开「预览当前草稿」核对。
5. 点击「保存草稿」。保存不会改变小程序正在展示的版本。
6. 超级管理员点击「发布到小程序」，小程序下次打开文档页面时读取新版。

两类文档分别保存、分别发布。内容编辑账号可以导入及保存草稿，发布由超级管理员完成；客服只读账号不能管理文档。生效日期是文档中的说明文字，当前发布按钮立即替换公开内容，不提供定时发布。

## Word 与排版

导入保留常用标题、段落、强调格式及列表。图片、页眉页脚、页码和 Word 的复杂版式不会按原样导入。小程序统一控制字号、颜色和段落间距。正文上限为 200,000 字符（含格式标记），超限明确报错，不截断条款。

Word 仅用于提取正文，原始附件不存入对象存储。标题、导语、日期和版本号仍在后台单独维护，导入正文不会自动猜测这些字段。

导入在受限工作线程中执行，最长 10 秒；归档最多 1,000 项、解压内容最多 20 MB，禁止外部文件访问。保存与读取均过滤 HTML，预览也过滤内容。网络错误及格式错误会保留现有草稿。

## 历史和冲突

「查看发布历史与旧版正文」展示最近 50 次发布，可查看正文，也可将某版载入本地草稿，再保存并发布为新版本。历史记录不被覆盖。

多个管理员同时编辑时，后保存或发布的旧编辑版本会收到冲突提示。本地内容保留，复制所需文字后重新载入最新草稿。后台切换栏目保留本地修改；刷新或关闭浏览器时，未保存内容会触发浏览器离开提示。

## 小程序

- 登录页展示用户协议与隐私政策阅读链接。
- 「我的 → 设置与隐私」提供两个独立入口。
- 沿用 `/pages/privacy-policy/index` 页面；用户协议使用 `?type=user-agreement`。
- 每次展示重新请求已发布内容；读取失败显示错误和重试按钮，不用内置旧条款代替线上文档。
- 用户协议首次发布前，公开接口返回 404，避免把占位文字当作正式协议。

## 数据和接口

新增迁移 `051_legal_documents.sql`，API 启动时由既有迁移器执行。它将现有隐私政策的草稿、公开内容、编辑版本、发布版本和发布时间复制到 `content_legal_documents`，旧表与发布历史保留。用户协议从未发布的空草稿开始。

| 接口 | 用途 |
| --- | --- |
| `GET /content/privacy-policy` | 已发布隐私政策，原 URL 保持可用 |
| `GET /content/user-agreement` | 已发布用户协议 |
| `GET /content/legal-documents/:key/manage` | 读取草稿和发布状态 |
| `POST /content/legal-documents/:key/import` | multipart `file` 导入，仅转换和预览 |
| `PATCH /content/legal-documents/:key/manage` | 带 `editVersion` 保存草稿 |
| `POST /content/legal-documents/:key/manage/publish` | 带 `editVersion` 发布 |
| `GET /content/privacy-revisions/:key` | 最近 50 次发布快照 |

`:key` 仅接受 `privacy-policy`、`user-agreement`。原隐私政策 `/content/privacy-policy/manage` 及发布 URL 保持兼容。接口统一禁止缓存；新增 JSON 正文上限为 1 MB，以容纳长中文条款。发布会写入快照及管理员审计。
