# 期刊首页内容发布流程

## 内容边界

小程序代码注册可渲染的栏目类型并拥有布局、样式、路由和交互；后台仅编辑栏目文字、媒体引用、启用状态和顺序。正文为纯文本，不允许上传 HTML、样式、脚本或自定义路由。观察入口携带期刊编号进入现有观察流程，“一起谈谈”打开本期讨论页；实践 Tab 的共同实践流程保持独立。

目前登记的栏目类型：`issueMeta`、`cover`、`opener`、`story`、`image`、`quote`、`audio`、`question`、`observationAction`、`sharedPracticeAction`、`contents`、`archive`、`brandFooter`。

本期讨论及“写下你的经历”文案和排版示例作为期刊 JSONB 草稿中的独立 `discussion` 对象编辑，与首页栏目分开。管理端“本期讨论页文案与示例对话”支持调整讨论页和写作页文字、增删示例经历及回应，并提供手机预览；保存仍沿用期刊草稿版本校验，发布时随同一期不可变快照。

## 后台操作

1. 在“内容运营 → 期刊与首页内容”新建或打开一期。
2. 编辑固定字段和栏目；可以添加允许的栏目类型、切换启用、上下移动或删除可选栏目。
3. 先保存草稿。草稿保存不会改变公开首页。
4. 打开已保存草稿，确认手机预览与发布历史；存在未保存修改时不能发布。
5. 点击“确认发布”。服务端校验栏目、必填内容与媒体，并在事务内写入不可变快照、切换当前期、归档旧期、记录审计并清理首页缓存。

当前已发布期迁移为版本 1。每次发布递增版本号；历史版本只读。媒体对象只要仍被任一草稿或发布快照引用，就不会进入可回收列表，也无法被删除。

## 接口

- `GET /content/home`：只读当前发布快照；继续返回既有 `issue`、`question`、`coverUrl`、`microVoice` 和 `sections` 兼容字段，并附 `publishedVersion` 与有序 `modules`。
- `GET /content/issues/:code`：只读当前发布快照中的期刊编号、标签和问题，供观察入口绑定快照。
- `GET /content/discussion?issueCode=ISSUE%2002`：只读指定期刊已发布快照中的讨论文案与示例对话；不传编号时读取当前发布期。
- `GET /content/issues`：管理端期刊草稿、草稿版本、发布版本及发布对照字段。
- `POST /content/issues`、`PATCH /content/issues/:id`：仅创建/更新草稿；更新通过 `editVersion` 做并发保护。
- `POST /content/issues/:id/publish`：单独发布，使用当前 `editVersion` 做并发保护。
- `GET /content/issues/:id/history`：管理端只读发布历史。

“写下我的经历”和“回复”输入时暂存于当前设备；用户点击保存后，经历正文以加密形式写入账户并进入运营审核队列，可在同一设备或重新登录后恢复，也可由用户放弃并删除。运营人员查看正文与变更处理状态都会写入审计日志。状态只有待处理、已处理和不采纳，不会自动发布到讨论页；公开讨论仍由期刊已发布快照提供示例内容。客服只读角色无权访问经历正文。

经历采用用户账户外键级联删除，账户删除会一并清除正文。账户数据导出包含已保存经历及审核状态。旧版设备内已有的经历不会在升级时自动上传；举报标记仍只保存在当前设备。

## 部署顺序

部署 API 时由现有迁移执行器自动应用 `047_content_issue_publications.sql` 与 `049_discussion_contributions.sql`。确认 API 健康和迁移账本一致后部署管理后台，再部署小程序。数据库升级不需要删除数据卷。旧版发布快照中的本机保存说明会在读取时忽略；新版小程序遇到未知栏目会跳过该栏目。
