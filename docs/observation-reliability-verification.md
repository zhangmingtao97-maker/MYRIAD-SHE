# 观察保存可靠性验收

本轮仅修改源码、编写用例和静态核对。以下运行验证尚未执行；须等用户允许统一编译/联调后再执行。支付、会员、商店和履约不在本验收范围，继续保持关闭。

API 响应会返回 `X-Request-Id`。缺失、过长或包含非安全字符的上游编号会被服务端替换为新的随机编号；异常响应体也会带同一编号。API 容器日志只记录编号、方法、路由模板、状态码和耗时，不记录令牌、请求正文或资源 UUID；未匹配路由统一记为 `<unmatched>`，不会回退记录原始路径。联调时可记录响应编号再定位请求。
API 全局响应还会设置 `X-Content-Type-Options: nosniff`、`X-Frame-Options: DENY` 和 `Referrer-Policy: no-referrer`；联调时可确认反向代理没有覆盖这些安全头。
健康检查的 PostgreSQL、MinIO、Redis 依赖调用分别受 `HEALTHCHECK_TIMEOUT_MS` 限制（默认 3 秒，服务端钳制在 100 毫秒至 10 秒）；依赖网络不返回时，`/health` 或 `/health/ready` 会在超时后明确标记对应依赖异常，不会让 Docker 探针无限等待。
API `PORT` 和 PostgreSQL 连接参数会在启动时严格解析和校验：端口必须是 1–65535 的整数，连接池大小在 0–100 范围内且 `DB_POOL_MIN` 不得大于 `DB_POOL_MAX`；`DB_CONNECTION_TIMEOUT_MS` 和 `DB_IDLE_TIMEOUT_MS` 分别限制连接建立与空闲连接回收；错误配置会快速失败，不会把环境字符串当作不确定的监听参数，也不会以 `NaN` 或异常大小启动，更不会无限等待数据库连接。
API 使用 Nest 优雅停机钩子；容器收到停止信号时会停止账户删除 worker 接受新轮询，等待在途轮询完成后再让数据库连接池、Redis socket、MinIO S3 客户端执行清理，避免滚动更新打断删除事务或遗留连接。
MinIO 内部端点和显式公网端点的端口都会在启动时严格校验；无效端口不会等到签名 URL 实际使用时才暴露。

本轮同时收紧微信登录响应契约：API 会去除凭证首尾空白，小程序只接受包含非空访问令牌、用户编号和正数有效期的成功响应；登录服务返回异常数据时不会污染本机登录状态，异常 2xx 也会保留响应请求编号。登录失败和普通 API 失败统一保留后端 `X-Request-Id`，方便从小程序提示回查服务端日志。
微信登录上游返回 `null`、数组或缺少 `openid` 时也会统一返回可恢复的认证错误，不会因直接读取异常响应字段而产生 500。
微信登录上游请求的超时计时器会持续到响应体解析完成；响应头已到达但响应体卡住时仍会中止请求，不会让云端会话长期停在等待状态。超时配置在服务端限制为 100 毫秒至 30 秒；管理员和小程序访问令牌有效期最多 30 天，异常的大值不会无限延长连接或会话。

小程序首页、实践和首页带入观察的本期问题共用公开内容响应守卫；观察草稿恢复失败时保留 API 请求编号，方便按编号回查服务端日志。管理后台的期刊、观察、隐私申请、审计和媒体列表也会先通过对应结构守卫，再更新运营界面状态。

小程序观察详情和数据导出响应中的答案只接受对应方法的字段白名单，单字段不超过 1000 字；未知字段或异常长度会保持错误态，不进入详情、恢复表单或剪贴板。

管理后台登录成功响应同样校验非空访问令牌和正数有效期；异常 2xx 不会写入浏览器会话。管理后台观察记录支持按“从现实处境开始/从四时气韵开始”、状态、期刊和超期草稿筛选；期刊筛选会去除首尾空白并限制 64 字符，审计操作筛选限制 120 字符；超长或未知枚举筛选在访问数据库前拒绝，不静默截断查询。观察列表和审计列表的当前页与筛选总数均使用同一 `REPEATABLE READ` 云端快照，避免并发写入造成分页总数自相矛盾。

历史答案保护的分页响应保持游标与 `hasMore` 一致：只有确实存在下一批记录时才返回最后一条记录游标；最后一批必须返回 `nextCursor: null`。管理端会拒绝两者不一致的响应，避免误发起重复扫描或把扫描显示为已完成。

公开首页内容现在使用 Redis 短 TTL 缓存，期刊创建或编辑前必须确认缓存失效；失效失败会回滚期刊事务并提示稍后重试，避免旧首页继续展示。普通首页读取在 Redis 不可用时仍回退 PostgreSQL，不改变 PostgreSQL 作为内容事实来源。管理后台健康卡会单独显示缓存依赖状态。

管理端媒体删除、期刊创建/编辑和实践配置保存响应均声明 `Cache-Control: no-store`，与答案重加密、删除申请执行和重试接口保持一致；联调时应确认代理不会缓存管理写操作结果。

管理后台退出或会话过期时会同时清除登录名和观察方式/状态/期刊/超期、隐私、审计筛选条件；上传失败后的临时媒体回收键与凭据仍留在当前浏览器会话，便于下一次登录继续清理。用户端观察记录分页的当前页和总数也使用同一 `REPEATABLE READ` 云端快照，删除或保存并发时不会混用两个时点的数据。

管理后台隐私申请、生命周期、登录和密钥保护响应守卫会限制编号、错误信息、时间戳、访问令牌和密钥 ID 长度；浏览器本地会话初始化也只接受不超过 16 KB、有效期不超过 30 天的令牌，异常云端字段或本地会话不会直接进入运营表格或保护结果。

媒体孤儿列表与观察、隐私、审计列表统一严格解析分页参数；非法 `limit` 在访问 MinIO 前返回 400，不静默回退到默认批次。

公开首页、实践和已发布期刊的客户端响应守卫与后端 DTO 使用相同的文本长度上限；Redis 首页缓存也使用同一边界。媒体孤儿响应要求 `hasMore` 与续页标记严格成对，管理端不会继续请求没有游标的下一页。

API 全局 DTO 管道拒绝未知顶层请求字段；联调时应确认拼写错误的写入字段收到 400，而不是被静默忽略。观察答案内部字段仍由观察方法白名单和长度校验处理。

管理后台 API 请求统一设置 12 秒超时，MinIO 媒体直传设置 90 秒窗口；值分别由 `VITE_API_REQUEST_TIMEOUT_MS`、`VITE_MEDIA_UPLOAD_TIMEOUT_MS` 配置并限制最大值，生产 Compose 会把配置传入 Vite 构建。超时会进入现有错误/重试状态，媒体对象键和临时清理凭据仍保留，不能把未确认的上传显示为已完成。

期刊管理列表返回 `editVersion`。管理员打开编辑表单后，保存必须携带该版本；每次修改和发布期自动归档都会递增版本。版本冲突时旧表单保存会锁定，管理员可载入最新版本：本地未修改字段采用云端值、本地已修改字段保留，未手动调整的状态采用云端状态；核对后才可再次保存，避免旧页面将过期发布状态写回。

管理后台总览同时读取期刊生命周期摘要、完整期刊列表和公开首页，并交叉核对各状态数量、当前发布期刊编号/更新时间、首页展示字段及发布媒体可用性。数据库约束要求已发布数量最多为 1，数量为 1 时编号与更新时间必须成对存在，数量为 0 时两者必须同时为空；有封面/音频引用时首页必须返回对应可用媒体，没有引用时首页不得带媒体；发布/编辑并发或媒体存储异常导致三个读取来自不同数据库/存储时点时，整次总览保持原数据并提示刷新，不展示互相矛盾的内容。观察治理区明确区分“当前筛选数量”和独立于筛选条件的全量生命周期摘要，避免把筛选列表规模误认为云端全量治理计数。

实践页面配置同样返回 `editVersion`。管理员保存页面文案和入口说明时必须携带该版本；版本冲突不会覆盖云端内容，后台会锁定本地表单，需显式放弃本地修改并载入最新版本后再继续。

实践页面文案和入口公开读取使用 `REPEATABLE READ` 事务快照；页面标题、说明和入口不会来自不同数据库版本。

## 接口约定

- 首页“带入一次观察”只传递当前已发布期刊的 `issueCode`；观察页再读取公开问题并在创建事务内写入标签/问题快照。问题详情的临时读取失败或返回格式异常会显示可重试提示和请求编号，不会丢掉编号，也不会把未经服务端确认的题目文本写入答案；若期刊已下架，服务端会拒绝创建新观察。
- 公开问题读取会修剪期刊编号首尾空白，并在长度不属于 2–64 个字符时直接返回 400，避免异常路径参数进入数据库查询。
- 首页没有已发布期刊时，“先从实践开始”进入实践 Tab；只有展示本期问题时才进入观察页并携带 `issueCode`，避免无期刊状态被误认为已有可关联问题。
- 两种观察方法的稳定名称以 H5 为准：`reality` 显示为“从现实处境开始”，`season` 显示为“从四时气韵开始”。方法键只用于 API 和恢复，不由客户端自定义扩展；恢复草稿以云端保存的方法和期刊快照为准。

- 用户记录列表的 `limit` 必须为正整数（省略时默认 30，最大 50），`offset` 必须为非负安全整数（省略时为 0）；非法分页参数返回 400，不会静默回退到第一页。
- `POST /observations` 新建时返回 `created: true`；恢复相同用户、相同 `clientDraftId` 的记录时返回 `created: false`。创建、恢复、详情和更新统一返回期刊快照、草稿标识、版本、创建时间和更新时间。
- 新建观察会在服务端修剪 `issueCode` 和 `clientDraftId` 首尾空白，再参与发布校验、幂等键和期刊快照写入；同一草稿不会因客户端空白差异生成第二条记录。
- 草稿 PATCH 必须携带详情或上次保存返回的 `revision`；版本过期返回 409，不覆盖较新的答案。小程序让用户选择载入云端，或二次确认后以本机完整回答覆盖。已完成记录的相同保存重试允许使用旧 revision 幂等返回，不重写答案或完成时间。
- 四时气韵的生日在 `SEASON_SAVE_BIRTH_DATE=false` 时只作为本次提交的瞬时校验输入：正式保存前仍必须提供真实的 `YYYY-MM-DD` 日历日期且不能晚于运行环境当前日历日，但加密答案、详情、导出和管理重加密结果都不得落生日字段；已保存记录的幂等重试可比较已脱敏答案。
- 先按用户与草稿标识加事务锁并恢复已有记录，再为新记录检查期刊发布状态。旧期刊归档不影响已创建草稿的恢复。复用草稿标识但切换方法或期刊会返回 409。
- 已完成观察仍只读。仅相同的 `status: saved` 和持久化答案可以重复提交；成功重试不重写密文、不刷新 `updated_at`、不再写完成审计。字段顺序不影响答案比较；不保存生日的策略在比较前生效。
- 用户传入其他账户的记录编号或草稿标识，不会取得该账户的数据。恢复与创建都限制在 JWT 认证用户范围内。
- `created: false` 不代表最新输入已经保存。小程序必须随后 PATCH 最新答案；最终保存也必须经过 PATCH 状态确认，不能只因 POST 返回已保存就宣称本次输入成功。
- 幂等 POST 恢复已有草稿后，后续 PATCH 必须使用该 POST 响应中的 revision；不能依赖异步页面状态更新完成后再读取版本号。
- 云端恢复草稿只展示创建时的期刊快照；不得通过最新公开期刊内容覆盖。缺失的历史快照不伪装成最新问题。
- 用户记录列表和管理后台列表同样优先读取这份快照；只有历史数据没有快照时才回退到期刊编号，避免归档后产生误导性的当前标签。

7. 自动保存尚未完成时快速连点下一步/保存：只推进一次；输入、上一步和下一步在显式保存期间禁用。等待自动保存结束后才执行显式保存。
8. PATCH 返回空记录或不符预期的状态：不进入完成页，不清空输入；保留编号，支持重试或返回“我的”刷新。
9. 恢复草稿或详情接口返回非对象答案：页面保持错误态，不把字符串、数组或其他异常结构写入表单/详情。
10. “我的”列表返回缺少分页字段、非法方法/状态或非对象条目：页面保持错误态，不把异常记录追加到本机列表；恢复、保存和详情使用同一记录守卫。
11. 管理后台观察、生命周期和历史答案保护接口返回缺少分页/计数/方式汇总/游标字段或未知结果枚举：运营表格保持原状态，并显示格式异常，不把扫描结果误报为完成。
12. 管理后台读取未引用媒体或回收媒体返回缺少对象键、保护期字段或审计结果：不把对象加入可删除列表，也不把删除失败显示为成功。
13. 两个 API 实例同时收到相同草稿标识的新建请求：只有一条记录和一条创建审计；各自返回 `created` 结果与数据库一致。此项须使用真实 PostgreSQL 验证事务锁和唯一索引。
14. 当前账号与另一个账号使用相同草稿标识：各自只能恢复自己的草稿；详情、更新仍受账户范围限制。
15. 两台设备恢复同一草稿：设备 A 保存后，设备 B 的旧版本自动保存返回 409 且不改变数据库；设备 B 选择载入云端后显示 A 的答案，或确认覆盖后以本机答案保存为新版本。若完成保存已提交但响应丢失，旧 revision 的相同最终提交应幂等返回当前完成版本。
16. 首页读取成功后点击“带入一次观察”：观察页显示同一期刊问题；在读取详情期间模拟网络失败，页面仍保留 `issueCode` 并允许继续，最终由服务端决定期刊是否仍可关联。两种方法名称与 H5 一致，恢复草稿不能被当前期刊文本覆盖。

## 小程序交互验收

- 首页重试、带入观察、实践页观察入口、观察方法选择和“我的”记录入口均使用原生按钮语义；隐私偏好使用原生 `switch` 的变更事件；加载、保存、冲突和禁用状态不允许重复触发请求。
- 观察页在自动保存或最终保存失败时显示显式“重试保存”按钮；重试沿用当前步骤和账户代次，最终步骤仍通过原有幂等 PATCH，不能绕过冲突确认。
- 首页按原型验收“当期策展 → 内容线索 → 微声音 → 此刻观察 → 目录”的阅读顺序；封面、音频、问题和目录均须来自公开首页响应，缺失媒体进入空态，不以占位内容冒充已发布内容。
- 实践页验收“主叙事 → 实践目录 → 观察入口/关闭入口”；我的页验收“观察记录 → 共同实践 → 选择与隐私”，账户删除、空态、错误态和分页重试仍沿用原有响应守卫。
- 管理后台验收五个分区按钮的选中状态、键盘焦点和窄屏换行；切换分区只改变展示范围，不改变已读取的数据、权限或危险操作确认流程。
- 观察方法选择区域在窄屏下不出现横向滚动，焦点/按压状态不改变布局；“载入云端”和“确认用本机覆盖”继续保留二次确认和明确的失败恢复提示。

## Redis 与公开内容联调清单（待执行）

1. Redis 可用时，连续读取首页只命中一次 PostgreSQL；首页缓存只包含公开期刊文本和媒体对象键，每次响应重新签名媒体地址，缓存 TTL 不超过配置上限。
2. 管理员创建、发布、编辑或下架期刊时，首页缓存失效动作在期刊事务提交前执行；失效失败时事务回滚，下一次读取不会看到未确认的新旧混合状态。
3. 首页缓存未命中与期刊发布并发时，旧回源请求不能在发布后的清缓存动作之后重新写入旧首页；内容锁释放后下一次读取必须得到新期刊。
4. Redis 停止或认证失败时，健康检查明确返回 `degraded` 和 `dependencies.redis = error`；首页仍能从 PostgreSQL 返回内容，且不会把空响应缓存为有效内容。
5. Redis 恢复后，健康检查重新返回 `ok`，缓存请求退出短暂熔断并重新使用 Redis。
6. Redis 命中旧版本或结构不完整的首页 JSON 时，API 回源 PostgreSQL，并用完整结构覆盖缓存。
7. Redis 停止时完整 `/health` 返回降级和 `redis = error`，但 `/health/ready` 仍可成功；Docker API 不因 Redis 健康检查失败而阻止启动，管理后台也不因缓存依赖故障被判定为未就绪。

## 期刊并发编辑联调清单（待执行）

期刊写入会统一修剪文本字段并把空媒体路径存为 `null`。`content_issue_code_exists` 表示需要修改编号；`content_issue_changed`、`content_issue_publish_conflict` 和 `content_issue_conflict` 表示需要刷新/合并云端版本；`content_home_cache_unavailable` 表示公开首页缓存暂时无法确认失效，期刊事务已回滚，管理后台应提示稍后重试，不能把这些状态误报为普通保存成功。

1. 两个后台会话打开同一期刊；会话 A 发布另一期期刊后，会话 B 使用旧表单保存应收到 409，不能恢复旧发布状态；旧表单保存按钮应锁定。
2. 会话 B 载入最新版本并合并：云端已变化且本地未修改的字段采用云端值，本地修改字段保留，未手动改状态时采用云端最新状态。核对后保存成功，`editVersion` 递增。
3. 编辑请求已提交但响应丢失后重试旧版本，应收到 409；载入最新版本后先核对上次保存结果，再决定是否继续提交，不能把不确定的旧状态覆盖回去。
4. 两个后台会话同时编辑实践页；旧 `editVersion` 保存应收到 `practice_content_changed`，本地表单保持锁定，载入最新版本后才允许继续保存。

## 连接配置核对

- Compose 环境应使用独立数据库参数，避免数据库密码包含 URL 保留字符时连接解析错误；非 Compose 运行方式可继续使用 `DATABASE_URL`。
- 生产配置校验会接受 `DATABASE_URL`，或接受完整的 `DB_HOST`、`DB_PORT`、`POSTGRES_DB`、`POSTGRES_USER`、`POSTGRES_PASSWORD` 组合；两者都缺失时 API 不应启动为生产服务。
