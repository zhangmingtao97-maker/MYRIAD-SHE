# 期刊后台信息架构与保存边界

## 一、后台菜单结构

```text
期刊
├─ 期刊列表     期号创建、状态总览、整期发布、发布历史
├─ 首页策展     刊期信息、封面主题、首页栏目编排、整期手机预览
├─ 人物故事     故事摘要、人物入口
├─ 微声音       本期音频、声音条目与文字稿
├─ 本期讨论     讨论页固定文案、示例经历、写作页预览
├─ 往期策展     首页「策展档案」入口 + 当前期之外的线上/归档期次
└─ 媒体库       全局图片/音频资产，独立于某一期

页面与协议
├─ 我的页面设置
├─ 关于 MYRIAD SHE
├─ 关于发布历史
├─ 用户协议
└─ 隐私政策
```

角色差异：

- `super_admin`：可见全部期刊与页面协议菜单。
- `content_editor`：可见期刊全部模块与页面协议；媒体回收等高风险动作仍只对超级管理员开放。
- `support_readonly`：不显示期刊菜单；页面协议中只保留「关于 MYRIAD SHE」「关于发布历史」等只读内容。

## 二、每个模块负责什么

| 二级模块 | 主要字段 | 对小程序的影响 |
| --- | --- | --- |
| 期刊列表 | 期号列表、状态、线上版本、草稿版本、发布时间 | 决定当前线上期；发布整期后替换首页 |
| 首页策展 | `code`、`label`、`month`、封面、人物摘要、声音、问题、观察入口、共同实践入口、目录、档案、页尾 | 首页按 `sections` 顺序渲染；启停、排序立即写入草稿 |
| 人物故事 | `story`、`storyAction` | 首页人物摘要与跳转入口，同属首页 `sections` |
| 微声音 | `audio` 及 `tracks` | 首页声音栏目；最多三段，无音频时不显示播放器 |
| 本期讨论 | `discussion.copy`、示例经历、写作页文案 | 讨论页固定文案，随本期一起发布 |
| 往期策展 | `archive` 栏目 + 当前期之外的线上/归档期次 | 首页档案入口；期次列表由状态自动生成，不手工维护 |
| 媒体库 | 图片、音频对象、未引用媒体 | 全局资源；保存期刊不会改动媒体库本身 |
| 页面与协议 | 我的页面、关于、协议、隐私政策 | 各自独立草稿与发布，不随期刊发布 |

## 三、整体修改还是单独修改

### 3.1 必须整期保存、整期发布

以下内容共用一份 `draftContent` 和同一个 `editVersion`：

- 期号信息：`code`、`label`、`month`；
- 首页栏目：封面、人物、声音、问题、观察入口、共同实践入口、目录、档案、页尾；
- 人物故事与人物入口；
- 微声音与声音条目；
- 本期讨论文案与示例经历；
- 往期策展入口文案。

原因：

1. 小程序首页按 `sections` 顺序一次性渲染，栏目增删/排序会影响整页结构；
2. 服务端发布以整期为快照，旧期归档、新期上线是同一个事务；
3. 如果拆成多个保存按钮，容易出现首页已更新、人物或声音仍是旧版的半发布状态。

因此后台保留一个「保存整份草稿」和一个「确认发布整期」，各二级模块只是同一份草稿的不同视图，不是独立数据表。

### 3.2 可以独立修改

| 对象 | 独立原因 |
| --- | --- |
| 媒体库 | 全局对象存储，可被任意期引用；上传、试听、未引用扫描不依赖当前期 |
| 期刊列表的创建/发布/历史 | 生命周期动作，不等同于某个栏目编辑；发布会读取当前整份草稿 |
| 往期期次列表 | 由 `published` / `archived` 状态派生，只读展示，不手工增删 |
| 页面与协议 | 每份文档有自己的草稿、版本与发布时间，不与期刊绑定 |
| 实践页文案 | 独立的实践内容管理；其中按期文案另有单独接口，不写入期刊 `draftContent` |

## 四、与小程序页面的对应

| 小程序页面/栏目 | 后台入口 | 说明 |
| --- | --- | --- |
| 01 首页 · 当期策展 | 首页策展 | 刊期信息、封面、首页栏目顺序、整期预览 |
| 01 首页 · 人物摘要/入口 | 人物故事 | 对应 `story` / `storyAction` |
| 01 首页 · 微声音 | 微声音 | 对应 `audio` 与 `tracks` |
| 01 首页 · 本期问题/讨论入口 | 首页策展 + 本期讨论 | 问题栏目在首页，讨论页文案单独编辑 |
| 01 首页 · 策展档案 | 往期策展 | 首页入口文案 + 当前期之外的期次列表 |
| 02 人物与档案 | 人物故事 + 往期策展 | 人物内容归故事，档案入口归往期 |
| 07 共同实践 | 实践 | 不属于期刊内容，未并入「期刊」 |
| 我的/关于/协议/隐私 | 页面与协议 | 各自独立草稿与发布 |

「观察记录管理」「用户经历审核」「隐私申请」「审计日志」等运营模块保持原一级菜单，不塞进期刊，避免把内容编辑与审核/合规操作混在一起。

## 五、这次实际改动

- 原「内容运营」一级菜单拆为「期刊」，下设 7 个二级模块。
- 原「协议与隐私管理」调整为「页面与协议」，把「我的页面设置」纳入同一分组。
- 期刊列表页补齐：全部期次、当前线上首页摘要、新建草稿、当前期概览、保存/发布/发布历史。
- 模块页补齐：当前期刊切换、模块内新增栏目、按模块过滤栏目、整期保存栏。
- 进入期刊模块时自动选中线上期或第一期；切换模块保留未保存草稿；保存后停留在当前模块。
- 本期主题/本期问题改为只读派生值，分别来自封面标题和「本期问题」栏目，避免两处维护。
- 媒体库增加全局说明，明确它不属于某一期。
