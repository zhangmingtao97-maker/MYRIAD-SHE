# 云端隐私生命周期验收

本文只用于后续统一联调。所有并发与故障注入场景必须在隔离、可销毁的测试数据库和测试账号中执行；不得对生产账号或共享环境执行删除验证。本阶段未连接数据库，也未执行这些步骤。

小程序隐私页会校验设置对象和删除申请状态；API 的设置读取与更新响应统一只返回通知开关、分析开关和合法 `preferences` 对象，不把历史未知顶层字段带回客户端。返回异常 JSON 时保持错误态，不会把未知状态当成可取消、已完成或可重新申请。收到 `account_deleted` 后会清空旧设置和删除申请状态，停止当前操作并提示回到“我的”页确认新账户。页面对同一认证代次的普通读取只保留一个在途请求；页面隐藏时会使读取代次失效，返回时可重新读取；认证代次变化时会强制读取新账户，旧请求的完成回调不能解除新请求的加载状态。
小程序启动时会把本机访问令牌限制为非空字符串且不超过 16 KB，把用户编号限制为 64 个字符，并只接受未来 30 天内的令牌过期时间；请求层不会把损坏的本机值拼入 `Authorization` 请求头。微信登录响应也使用相同边界，异常令牌、用户编号或超长有效期会停留在登录失败态。
后端用户与管理员认证守卫同样拒绝超过 16 KB 的 Bearer 令牌，用户 JWT 的主体编号限制为 64 个字符；微信登录上游的 openid、unionid 和错误文本在写入用户表或返回客户端前也会经过长度限制。
用户认证守卫还要求 JWT 主体匹配规范 UUID，非法主体不会进入用户表查询。
小程序“我的”页的云端记录读取采用相同的页面级去重策略；普通列表读取在页面隐藏时失效，返回页面时重新读取；账户重建后先清空旧列表，再强制读取新账户，即使旧账户请求仍未结束也不会阻塞新账户的首次读取，避免快速切换页面产生重复请求或短暂显示旧记录。
首页与实践页的公开内容读取也在页面隐藏时失效并恢复为可刷新状态；返回页面后重新读取云端期刊、问题和入口，避免旧快照或过期签名媒体地址回写。
隐私页离开到后台时，已经由用户确认的设置保存、数据导出和删除申请不会被页面代次误取消；请求完成后会清除忙碌状态，返回页面即可继续读取。普通读取刷新仍会失效，避免旧响应覆盖返回后的新状态。记录详情页的已确认单条记录删除遵循同样原则，页面隐藏时允许删除收尾，普通详情读取则在离开页面后失效。
数据导出在服务端先按公开设置契约过滤未知顶层设置字段，并将超过 16 KB UTF-8 字节的历史 `preferences` 归一为空对象，再按观察方法白名单和单字段 1000 字上限最小化答案，未知字段不会离开 API；导出事务使用 `REPEATABLE READ`，让设置、观察记录和删除申请状态来自同一个云端时间点；若账户删除提交恰好造成 SQLSTATE `40001`，服务端只重试一次新的导出事务，避免把瞬时序列化错误暴露给用户；小程序复制到剪贴板前会复用完整 `UserSettings` 守卫，并校验导出版本、账户元数据、观察答案、删除申请字段和偏好大小，格式异常时保持导出失败状态。
观察答案加密封装限制 64 KiB 明文和 256 KiB Base64 载荷；超过上限的历史密文只会在管理迁移扫描中标记为无效，不能进入解密、导出或重新加密路径。
管理后台删除申请分页和执行/重排结果会校验状态、计数和结果枚举；分页响应会在同一 `REPEATABLE READ` 云端快照中校验当前页、筛选总数，以及独立于状态筛选的全量待处理、可领取到期、有效处理中租约、过期租约、失败、已完成、已取消、最早待处理和下一次可领取时间摘要。可领取到期与 worker 使用同一处理租约时长；有效租约释放前，管理员手动执行也不会接管；过期租约会单独提示 worker 可再次领取，未知响应不会被显示为已完成或已重新排队。

## 账户删除与并发写入

准备一个测试账号、一条到期的删除申请、一条观察记录和至少一条 `actor_id` 指向该账号的用户审计记录。并发场景需使用独立数据库连接，并在关键语句间设置屏障，确保操作顺序可控。

1. **导出先取得锁**：导出事务共享锁定用户行和观察行后暂停；启动到期账户删除。删除事务必须先以 `FOR UPDATE` 锁定用户行，再锁定观察行，最后锁定并复核删除申请，因此会在用户锁或观察锁处等待，不得与导出形成互等。恢复导出并提交后，删除继续完成。最终用户和观察记录不存在；删除申请为匿名完成状态；导出审计存在但 `actor_id` 与 `resource_id` 均不含用户编号。
2. **删除先取得锁**：账户删除事务以 `FOR UPDATE` 取得用户行锁后暂停；启动导出。删除提交后，导出应以账号不存在结束，不能返回空设置或空记录，也不能新增 `privacy.data.exported` 审计。
3. **设置更新并发**：让设置更新先以 `FOR UPDATE` 锁定用户行，再暂停在写入或审计阶段，随后启动账户删除。设置事务提交后删除继续；最终用户设置审计已匿名化，账号与观察记录均已删除。
4. **观察写入并发**：分别覆盖创建草稿、更新草稿和删除单条记录与账户删除交错。每个完成的观察操作可以在线性顺序上先于账户删除；账户删除最终提交后，不保留该账号的观察记录或可识别其身份的用户审计字段。JWT 守卫通过后若账户已删除，列表、详情、创建、更新和删除仍应返回 `account_deleted`，不能伪装成空记录或 `deleted: false`。

管理登录的来源地址按 `TRUST_PROXY_HOPS` 解释反向代理链；默认值为 0，未配置可信代理时不采信转发头，避免账号/来源双维度失败锁定被伪造。

管理登录账号的首尾空白会在服务端统一去除，密码不做修剪；验收时应确认带首尾空白的正确账号仍能登录，且失败锁定与审计记录使用规范化账号。

设置读取/更新、导出、用户删除申请接口和账户删除采用一致的账户锁前缀：先锁定用户行。导出随后共享锁定观察行；账户删除任务再锁定观察行，最后以 `FOR UPDATE` 锁定并复核删除申请的状态、到期时间和用户归属，只有复核仍为待处理时才删除观察与账户；申请创建/取消若与账户删除并发，会等待账户锁并在账户已消失时返回 `account_deleted`，不会落成外键错误。验收时要确认这套顺序不会产生互等，并且删除提交后设置读取与导出不会返回空的“成功”结果。

同一 API 实例内的删除轮询具有互斥保护：上一轮尚未结束时，定时器触发的新一轮会直接返回，不会重叠扫描；多个 API 实例仍依赖数据库处理租约和账户/观察/申请锁协调。验收时可让一次 `processDue` 人为延迟，再触发第二次调用，确认第二次不新增数据库扫描。

删除轮询间隔最多 1 小时，处理租约和基础重试退避最多 24 小时，单次重试退避最多 7 天，最大自动尝试次数最多 100 次，账户删除冷静期最多 3,650 天；超出范围的配置会被服务端钳制，避免计时器溢出或指数退避失控。

观察写入、设置更新和删除申请写响应均带 `Cache-Control: no-store`；联调时应确认代理不会保留答案或账户状态响应。

## 事务失败与重试

在隔离数据库中通过测试专用约束或触发器，让删除事务的审计去标识语句失败。确认账户、观察记录、隐私申请完成状态以及删除事务内的审计插入一起回滚；后续失败重试状态按配置持久化，不能留下“账户已删除但审计仍可识别”的半完成状态。移除故障注入后，再验证重试最终完成且可重复执行不会重复产生删除副作用。

## 小程序账户删除状态

以下场景只可使用隔离测试账号与测试环境微信配置执行；当前仅完成源码静态核对，未编译或联调。

1. 删除任务完成后，从旧页面触发任一受保护请求：API 返回稳定错误码 `account_deleted`（同时保留用户可读提示），小程序识别后清除本机访问令牌并跳转到“我的”；微信登录接口不应因该请求被自动调用。隐私页、观察填写页和记录详情页要清空旧云端状态并停止后续写入；观察页隐藏/卸载时不能再冲刷自动保存。
2. 关闭并重新打开同一安装：删除状态仍保留，不自动创建空账户；“我的”页不显示旧观察记录，并提供明确的新账户入口。
3. 在确认弹窗中取消：不发起微信登录，删除状态保持；确认创建后才调用微信登录，成功后显示空记录列表。若旧的观察填写页或记录详情页仍在导航栈中，回到页面后必须清空旧草稿/记录编号、答案和自动保存任务。
4. 明确创建新账户时遇到网络或登录失败：本机删除状态恢复，后续请求仍不会自动登录；重试需再次由用户触发。
5. 旧账户请求在新账户创建后才返回 `account_deleted`：旧响应不能把新账户再次标记为已删除或清除新账户令牌；只有认证代次和令牌仍匹配时，才允许切换到删除态。旧请求收到其他 401 时也不能跨认证代次自动重试；即使旧请求返回 2xx，也不能把响应写回新账户页面。

删除状态目前保存在小程序本机，应用数据被清除或换设备后不会保留。跨安装阻止同一微信身份自动重建账户，需要另行确认服务端删除身份标识的保留方式与期限；本阶段不存储或保留该标识。
