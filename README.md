# MYRIAD SHE

当前工程结构：

```text
miniprogram/  微信小程序原生 TypeScript
backend/      NestJS / Node.js API
management/   Vue 3 + Vite 管理后台
docker-compose.yml
```

## Docker 开发环境

所有服务使用根目录 `.env.local`。部署到 `192.168.5.99` 时，在项目根目录执行：

```bash
docker compose --env-file .env.local up -d --build
docker compose --env-file .env.local ps
docker compose --env-file .env.local logs -f api
```

服务地址：

- API：`http://192.168.5.99:61021/api`
- 管理后台：`http://192.168.5.99:61022`
- PostgreSQL：`192.168.5.99:61023`
- Redis：`192.168.5.99:61024`
- MinIO API：`http://192.168.5.99:61025`
- MinIO Console：`http://192.168.5.99:61026`

小程序使用微信开发者工具打开 `miniprogram/`。项目已启用 TypeScript 编译插件，页面逻辑以 `.ts` 为唯一源码；开发设置中的请求域名需要允许 `192.168.5.99:61021`，或使用开发者工具的“不校验合法域名”选项进行局域网联调。

数据库结构统一由 API 启动迁移器管理，不再依赖 PostgreSQL 数据卷的首次初始化目录。API 开始监听前按版本顺序执行尚未登记的 `backend/sql/` 脚本，并在 `app_schema_migrations` 中记录文件名与 SHA-256 摘要；执行使用 PostgreSQL advisory lock 串行化。已登记脚本若被改写，或账本中存在但镜像缺失的迁移文件，都会阻止 API 启动；已有数据卷无需删除。管理后台总览还提供只读的迁移账本状态，可识别待执行、缺失或被修改的迁移文件，不提供通过页面执行迁移的入口。

生产服务 HTTPS 主入口为 `https://hszfckga.com`，`https://www.hszfckga.com` 也可直接访问同一站点；API 为 `https://hszfckga.com/api`，管理后台由根路径提供。生产 Compose 只向公网发布 80/443，MinIO 管理 API 仅绑定服务器回环地址；私有配置和初始化数据库备份分别保存在服务器 `/opt/myriad-she/.env.production` 与 `/data/backups/myriad-she/`。

小程序源码默认连接正式 HTTPS API。使用微信开发者工具真机体验或发布前，需在小程序后台将 `https://hszfckga.com` 配置为合法 request、uploadFile 和 downloadFile 域名；`miniprogram/project.config.json` 的 `urlCheck` 仅用于本地开发工具设置，不会替代平台域名配置。

## 当前第一阶段能力

- API 健康检查、就绪检查、首页内容和实践内容接口；完整健康检查验证 PostgreSQL、MinIO 与 Redis，依赖异常时返回逐项状态且禁止缓存；每项依赖检查受 `HEALTHCHECK_TIMEOUT_MS`（默认 3 秒，服务端限制在 100 毫秒至 10 秒）约束，异常网络不会让探针无限等待；Docker 就绪探针只要求 PostgreSQL 与 MinIO，Redis 降级不会阻止 API/管理后台启动
- API 为每个请求生成或透传安全的 `X-Request-Id`；响应头始终返回该编号，异常 JSON 也包含同一编号，容器日志只记录编号、方法、路由模板、状态码和耗时，便于从小程序或管理后台反馈后定位请求且不记录令牌、正文或资源 UUID；未匹配路由统一记为 `<unmatched>`，不会回退记录原始路径
- CORS 仅向管理后台暴露 `X-Request-Id` 诊断响应头，不暴露令牌或其他内部响应头
- API 全局响应设置 `X-Content-Type-Options: nosniff`、`X-Frame-Options: DENY` 和 `Referrer-Policy: no-referrer`，与生产管理后台 Nginx 的安全响应头保持一致
- 后端单元回归还覆盖完整健康检查与 Redis 降级时的就绪探针语义
- Redis 通过内置 RESP 客户端接入健康检查和首页公开内容缓存；读取失败时回退 PostgreSQL，缓存 TTL 默认 60 秒；期刊创建或编辑必须确认首页缓存已失效，确认失败会回滚写事务并提示稍后重试，避免旧首页继续展示
- 首页缓存命中前会校验缓存结构，旧版本或异常 JSON 不会遮蔽 PostgreSQL 内容；缓存只保存公开期刊文本和媒体对象键，每次响应重新签名媒体地址，避免复用已过期签名
- 首页缓存未命中时会与期刊写入共用内容锁并在锁内二次检查；期刊事务提交前完成首页缓存失效，且失效无法确认时回滚期刊写入，避免旧回源请求在发布后重新写回旧首页
- Redis 客户端支持 `redis://`、`rediss://`、独立密码、逻辑数据库和连接超时配置，不把 Redis 密码拼入 URL 或写入业务日志
- Redis 及 MinIO 的回退端口和显式 `redis://`/`http(s)://` 端点端口都会在 API 构造依赖时严格限制为 1–65535，非法端口会快速失败，不会等到首次业务请求才暴露
- PostgreSQL 支持独立连接参数或外部 `DATABASE_URL`；生产 Compose 默认使用独立参数，数据库密码不需要拼接进 URL
- API `PORT` 与 PostgreSQL 的 `DB_PORT` 都会从环境字符串严格转换为 1–65535 的整数；`DB_POOL_MIN`/`DB_POOL_MAX` 分别限制在 0–100 和 1–100，且最小连接数不能超过最大连接数；`DB_CONNECTION_TIMEOUT_MS`（100–30000 毫秒）和 `DB_IDLE_TIMEOUT_MS`（100–600000 毫秒）限制连接建立及空闲回收；配置错误会在 API 启动时明确失败，避免监听行为不确定、生成异常连接池或无限等待数据库连接
- Compose API 环境显式清空旧 `DATABASE_URL`，统一使用 `DB_HOST`、`DB_PORT` 和 `POSTGRES_*` 参数；直接运行 API 时仍可提供 `DATABASE_URL`
- API 启动时会清理 `CORS_ORIGIN` 多地址配置中的空格，避免合法管理后台来源因格式空白被拒绝
- API 会按 `TRUST_PROXY_HOPS`（默认 0，最多 10 跳）配置 Express 可信代理，确保管理登录失败策略读取到正确的来源地址；未显式配置时不信任转发头
- API 全局 DTO 校验会拒绝未知顶层请求字段，不再静默丢弃拼写错误或未纳入契约的写入参数；观察答案对象内部仍由方法白名单单独校验
- 观察、隐私、管理治理和审计读取接口统一禁止缓存，避免带账户或运营信息的 GET 响应被中间层保留
- 观察创建/更新/删除、用户设置更新和删除申请写接口也明确禁止缓存，返回的答案与账户状态不会依赖中间层默认行为
- 管理后台答案重加密、删除申请执行和重试响应同样明确禁止缓存
- 管理后台媒体删除、期刊创建/编辑和实践配置保存响应也明确禁止缓存，避免代理保留管理写操作结果
- 管理后台总览分别展示 API、PostgreSQL 和 MinIO 健康状态，便于联调时定位依赖故障
- 管理后台解析 API 错误时会显示服务端请求编号，运营反馈失败信息时可直接关联 API 容器日志
- Docker Compose 使用 API 健康检查后再启动管理后台，避免后台早于数据库/MinIO 就进入错误态；API 启动只等待 PostgreSQL，Redis 作为可降级缓存不再阻塞 API 容器启动
- API 启用 Nest 优雅停机钩子；容器重启或滚动更新时会停止账户删除 worker 接受新轮询，等待在途轮询完成后再释放 PostgreSQL 连接池、Redis socket 和 MinIO S3 客户端
- 微信登录接口骨架和本地管理后台登录
- 微信登录会在 API 与小程序两端校验令牌、用户编号和过期时间字段；异常的 2xx 响应不会被写入本机登录状态，仍会保留响应请求编号
- API 到微信登录上游的超时覆盖响应头和响应体解析，异常或卡住的上游不会让云端会话请求无限等待
- 微信登录上游等待时间在服务端限制为 100 毫秒至 30 秒；管理员和小程序访问令牌有效期最多 30 天，异常的大值不会把连接或会话无限延长
- 微信登录会拒绝 `null`、数组或缺少 `openid` 的微信响应，避免上游异常被转成 API 500
- 管理员和微信登录响应明确禁止缓存，令牌不会被中间层复用
- 管理后台退出或会话过期时会清空登录名、筛选条件、表单冲突、分页失败、隐私操作结果和答案保护游标等非持久状态；上传失败后的媒体回收键与凭据仍保留在当前浏览器会话中，便于后续清理
- 管理后台初始化会校验浏览器本地令牌和过期时间；登录响应令牌不超过 16 KB、会话最长 30 天，损坏或异常会话不会进入 API 请求
- 管理后台 API 请求统一有 12 秒超时，MinIO 媒体直传使用 90 秒窗口；网络中断时会结束忙碌状态并保留可重试/回收线索，不会无限停在处理中
- 管理后台 API 与媒体直传超时分别由 `VITE_API_REQUEST_TIMEOUT_MS`、`VITE_MEDIA_UPLOAD_TIMEOUT_MS` 配置，并限制最大值；本地默认 12 秒/90 秒，生产 Compose 会把 `.env.production` 的值传入 Vite 构建
- 观察记录 PostgreSQL 表结构和保存接口基础
- 小程序首页、实践、我的、此刻观察入口
- 小程序首页与实践页在重新显示时刷新云端内容，用请求代次隔离旧响应，并提供云端内容读取失败后的重试；页面隐藏时会失效普通读取并恢复可刷新状态，避免旧期刊快照或已过期签名媒体地址在返回后回写；首页失败时会清理旧的签名媒体
- 小程序首页和实践页会先校验公开内容响应结构；实践入口按键集合和开放闸门校验而不依赖后台返回顺序，异常 JSON 进入错误态并可重试
- 小程序首页、实践及首页带入观察的本期问题共用内容响应类型守卫；后台返回字段异常时不会把不完整内容写入页面状态
- 小程序微信登录和 API 请求默认使用 8 秒超时，单次请求可显式覆盖
- 小程序微信登录与普通 API 请求统一保留后端 `X-Request-Id`；登录失败也会显示请求编号，便于按服务端日志定位问题
- 小程序 API 失败对象会保留服务端 `X-Request-Id` 并在错误文案中显示，网络未到达 API 时不伪造请求编号
- 小程序首页、实践、我的、隐私和详情页不会抹掉 API 错误编号；本地网络失败仍显示各页面的友好兜底文案
- 管理后台查看 API 状态和当前首页内容
- 管理后台维护期刊、本期问题及发布状态
- 实践页标题、说明及三个入口由 PostgreSQL 云端管理，更新写入管理员元数据审计
- 实践页保存带云端 `editVersion` 并在事务内复核，多个管理员同时编辑时拒绝旧版本覆盖并要求重新载入
- 实践页公开读取在 `REPEATABLE READ` PostgreSQL 事务快照中读取页面文案和三个入口，避免更新提交期间拼出跨版本内容
- `此刻观察` 入口由 API 和数据库约束为始终开放；共同实践在活动内容流程接入前固定关闭；`日常之物` 在商店规则确认前由 API 和数据库约束为关闭
- 两种观察方法的四步流程、云端草稿和观察记录详情
- 首页本期问题作为观察上下文保留并关联到云端记录
- 首页带入观察时，即使本期问题详情短暂读取失败也会保留 `issueCode`，恢复后仍由服务端写入期刊快照
- 首页带入观察时，本期问题读取失败会在观察入口显示可重试提示和请求编号，但不会误锁住观察方式选择；服务端仍会在创建时重新确认期刊是否已发布
- 首页没有已发布期刊时，“先从实践开始”会进入实践 Tab；只有本期问题卡片才进入观察并携带期刊编号
- 两种观察方法名称固定为“从现实处境开始”和“从四时气韵开始”，首页入口只传递期刊编号，服务端在创建事务内确认发布状态并保存问题快照
- 公开期刊问题读取会修剪编号首尾空白并限制 2–64 个字符，异常参数在访问数据库前直接拒绝
- 我的页面云端记录列表、草稿续写与登录过期恢复
- 小程序首页和实践页按公开内容访问，不会在启动时强制登录；进入观察、我的或隐私设置时才按需建立云端会话
- 设置与隐私、云端删除申请及冷静期取消
- 管理后台观察记录元数据治理
- MinIO 图片/音频临时上传地址接口
- 管理操作审计记录与到期账户删除任务
- 期刊发布、自动归档和媒体回收审计会记录管理员身份
- 管理后台期刊封面/微声音直传 MinIO，并可通过管理员专用短时预览地址确认尚未发布的媒体；公开媒体预览仍只允许已发布期刊引用的对象
- 未引用的期刊媒体可由管理员安全回收，仍被任何期刊引用的对象不可删除
- 期刊创建、媒体字段变更或草稿转发布时，会由 API 通过 MinIO HEAD 校验相关媒体对象存在且类型匹配
- 管理后台媒体上传签名会校验文件字节数并把大小约束传递给 MinIO，使用 `UPLOAD_MAX_FILE_SIZE_MB` 控制上限
- 媒体上传文件名和 MIME 类型不能为空；后台只接受 HTTP(S) 上传签名地址，不会把异常协议交给浏览器直传
- MinIO 客户端会识别带协议的端点，并按 `MINIO_USE_SSL` 为未带协议的内部/公开端点选择 HTTP 或 HTTPS
- MinIO 内部端点和显式公网端点的端口都会在启动时严格校验，避免签名上传/下载 URL 使用无效端口到运行期才失败
- 期刊创建、媒体字段变更或草稿转发布时，会再次读取 MinIO 实际对象大小，超限对象不能被正式内容引用
- 期刊媒体类型按上传 MIME 白名单精确校验；创建期刊的对象校验与媒体回收共享事务锁，避免并发删除造成悬空引用
- 首页及公开媒体签名时复核对象实际类型和大小；管理后台在直传前登记对象键，上传失败后仍可重试回收
- 公开期刊详情和实践配置也禁止缓存，确保内容运营发布后用户进入观察时读取到最新版本
- 首页每次重新显示时刷新已发布内容和媒体签名地址，含时效签名的公开响应禁止缓存
- 期刊媒体的 HEAD 元数据不完整时也不能被正式内容引用
- 首页和公开媒体地址只会为仍存在的 MinIO 对象签名
- 管理后台可分页扫描超过 `CONTENT_MEDIA_ORPHAN_GRACE_HOURS`（默认 24 小时）且未被期刊引用的 MinIO 媒体；孤儿删除时服务端重新读取修改时间并复核保护期和引用，期刊上传地址会签发绑定管理员与对象键、24 小时有效的临时清理凭证；不会自动清理
- 管理后台媒体孤儿分页与观察/隐私/审计分页使用同一严格参数解析，非法 `limit` 在访问 MinIO 前返回 400，不会静默扫描默认批次
- 小程序与管理端对首页、实践、期刊响应执行与后端 DTO 一致的长度边界校验；媒体孤儿续页标记会先去除首尾空白再访问对象存储
- 管理后台媒体列表响应要求 `hasMore` 与续页标记严格一致，避免“无下一页仍带游标”或“有下一页但无法继续”的错误状态
- 媒体删除在内容会话锁内完成引用检查，先提交删除发起审计再删除对象，之后追加成功或失败审计；完成审计不可用时仍保留发起记录并明确反馈
- 期刊保存后的批量媒体回收会区分对象删除失败与删除审计失败，并保留“期刊已保存”的真实结果
- API 更新期刊、用户设置和观察状态时会拒绝非空字段的显式 `null`，可清空的期刊媒体字段仍支持 `null`
- 当前只允许一期期刊处于已发布状态；发布新期刊会在同一事务内归档旧期刊
- 管理后台发布或下架期刊时进行二次确认，状态变更审计记录前后状态和期刊编号
- 期刊创建与编辑会在服务端修剪文本首尾空白、把空媒体字段归一为 `null`；编号重复、发布并发、版本冲突和公开首页缓存不可用返回不同错误码，后台只对可合并的编辑冲突锁定表单，缓存不可用时不会把未确认的期刊写入数据库
- 管理后台观察记录按观察方式/状态/期刊筛选，并支持超期草稿筛选；观察列表当前页与筛选总数在同一 `REPEATABLE READ` 云端快照中读取；审计列表当前页与筛选总数也使用同一快照；账户删除申请到期后人工执行入口，期刊发布二次确认
- 用户端观察记录分页的当前页与总数也在同一 `REPEATABLE READ` 云端快照中读取，删除或保存并发时不会展示互相矛盾的记录数量
- 管理后台观察期刊筛选会去除首尾空白并限制 64 字符，超长筛选在访问数据库前拒绝
- 超期草稿筛选启用时锁定为草稿状态，退出筛选后恢复原状态条件，避免与“已保存”筛选组合成空结果
- 草稿治理当前只提供统计与只读筛选；保留期限、永久删除、恢复窗口和用户告知策略未确认前，不提供自动或批量清理入口
- 管理后台观察记录支持分页加载，筛选后从第一页重新读取并保留失败重试状态

- 观察生命周期统计将历史明文、封装字段齐全和字段异常分开展示，不读取观察正文；是否可解密由轮换扫描验证
- 观察记录治理支持按配置期限筛选超期草稿，仍只读展示，不执行自动或批量删除
- 最终提交在创建响应丢失时会先幂等恢复草稿，再更新为已保存状态
- 四时气韵中的生日按 `SEASON_SAVE_BIRTH_DATE=false` 处理，只用于本次计算，不写入云端；迁移直接清理历史明文，已加密记录由管理后台分批保护/重加密扫描解密脱敏后重新加密，均不改写内容更新时间
- 四时气韵最终保存会先验证本次提交包含完整的生日输入，再按隐私策略脱敏加密；生日不会因为默认不存储而导致流程无法完成
- 四时气韵最终保存会拒绝非真实 `YYYY-MM-DD` 日历日期和运行环境当前日历日之后的日期；日期控件不能替代服务端校验
- 对包含历史生日字段的旧四时草稿，即使最终保存请求未附答案、只提交状态变更，也会在校验后剔除生日再写入
- 生日策略同时在 API 读取端脱敏，迁移尚未执行时也不会重新返回历史生日
- 管理写接口具备 PATCH 字段校验，UUID 路径参数在服务端校验
- 商店、会员、支付、履约均保持关闭，且支付/履约不使用 mock
- 生产环境启动校验会拒绝商店、会员、付费会员、支付或履约开关被误设为 `true`；`.env.production.example` 显式保持这些开关为 `false`，规则和真实服务配置确认前不会提前开放入口

商店和会员规则确认后，再进入商品、订单、售后和会员权益模块开发。数据库升级由 API 启动时的迁移执行器完成；上线前仍应先备份 PostgreSQL 数据卷。删除账户后，系统保留不含用户标识的删除申请和审计状态；观察记录保留创建时的期刊问题快照；MinIO 浏览器上传跨域通过项目容器的 `MINIO_API_CORS_ALLOW_ORIGIN` 配置，不修改主机上其他 MinIO 服务。

观察保存的接口约定、后端单元用例和待联调清单见 [观察保存可靠性验收](docs/observation-reliability-verification.md)。迁移状态新增用例之前的远端隔离环境已执行后端单元测试 107/107 通过；当前源码新增用例尚未重新执行。真实 PostgreSQL、Redis、MinIO、微信真机和完整端到端联调仍未完成，不得把单元测试结果当成部署验收通过。
